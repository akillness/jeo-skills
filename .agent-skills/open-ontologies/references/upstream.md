## Source-verified operation

- Pinned `Cargo.toml` declares the Rust binary `open-ontologies`, package version `2.1.0`, and an MIT license. Its feature set includes optional SQL/Postgres, DuckDB, embeddings, plugins, and other modules. Use the installed binary's own `--help` for the exact command surface; source currently defines `serve` (stdio MCP), `serve-http` (Streamable HTTP), Unix-socket service on Unix, `batch`, validation/query/diff/lint commands, and reasoning/data/versioning commands.
- The README's batch example is `printf 'load base.ttl\\nplan proposed.ttl\\n' | open-ontologies batch -`. It also shows certificate checking with `oo-cert asserted.tsv derivations.tsv` and Lean checker examples. These are documented procedures, not authorization to execute, install, build, or mutate data.
- Pinned `.mcp/server.json` is a separate MCP package declaration: metadata version `0.1.9`, OCI identifier `ghcr.io/fabio-rovai/open-ontologies:0.1.9`, and `stdio` transport. Do not conflate that metadata with Cargo package version `2.1.0`; downloading/running the image, building source, registering a client, or starting any listener requires approval. Source `serve-http` exposes a different transport, binds the configured host/port, optionally checks a bearer token, leaves `/health` unauthenticated, and applies permissive CORS; review and explicitly approve those exposure settings before use.
- The project is a semantic analysis, planning, reasoning, and certification engine, not a GUI editor. It covers RDF/OWL, SHACL, SPARQL and related workflows, but unsupported constructs, budget limits, and incomplete/undetermined results remain first-class outcomes. A certificate's scope is tied to its encoded rules and artifacts: distinguish built-in-rule conclusions, supplied-rule conclusions, prover opinions, and independently checked certificates.

## Verified build and runtime (observed 2026-10-29, macOS arm64)

These facts come from running the pinned commit on one Apple Silicon host; they are host evidence, not a platform matrix.

- `scripts/install.sh` encodes the procedure: clone `dfb09bf8…` with `--filter=blob:none`, run `preflight.py`, `cargo build --locked` into a separate `--target-dir`, copy the binary, run `scripts/smoke.py`. First builds download crates plus the pinned Oxigraph Git patch (`fabio-rovai/oxigraph` rev `abf36ef2…`); `--offline` fails before compiling when that patch is not cached.
- Toolchain floor is **1.88**: `cargo metadata --locked` lists `darling 0.23.0` (`rust-version 1.88.0`) as the highest requirement in `Cargo.lock`; the Oxigraph patch declares `1.87`; `open-ontologies` itself declares no `rust-version` (edition 2024). cargo **1.87.0 refused** the locked set with "rustc 1.87.0 is not supported by the following packages: darling…". The README's "Rust 1.85+" is therefore not sufficient for this lock file. Verified builds: `cargo +1.99.1` dev profile (7m16s) and release profile (see the `install.sh` log timing in the catalog pilot report).
- Default features are empty (`default = []`); `postgres`, `duckdb`, `sql`, `embeddings`, `causal-pywhy`, `plugins`, `turbovec` are opt-in and were not built. `oxrocksdb-sys` (via Oxigraph) uses `bindgen` and `cc`, so a C/C++ compiler and libclang are required even for the default build; Apple clang 21 sufficed.
- The binary has no `--version` flag (clap rejects it); identify it by the first `--help` line, "Terraform for Knowledge Graphs — AI-native ontology engine".
- `batch -` accepts a JSON array of `{"command": ..., "args": [...]}` objects; `query` wants a single SPARQL string argument (split arguments are rejoined). `reason --profile rdfs` over two triples (`invokes rdfs:subPropertyOf dependsOn`, `ci invokes validator`) reported `inferred_count: 1`, `fixpoint_reached: true`, and the derived `ci dependsOn validator` row became queryable. `scripts/smoke.py` asserts exactly this and nothing more.

## Preflight helper contract

From the `jeo-skills` repository root, run `python3 .agent-skills/open-ontologies/scripts/preflight.py --repo /absolute/upstream --json`. From an installed skill root, run `python3 scripts/preflight.py --repo /absolute/upstream --json`. The source argument must be an authorized absolute directory with no symlink path components. The helper is Python-stdlib-only and read-only: it discovers `python3` with `PATH`, reads the skill-local manifest, and hashes only its listed public regular files (bounded to 8 MiB each). It does not use the network, spawn subprocesses, execute upstream code, read secret files, verify Git HEAD, inspect unlisted files or dependencies, or establish runtime readiness.

The JSON report uses `source_checked: true` only after selected files were inspected and always reports `runtime_verified: false`. Exit `0` means the offline report completed with all selected hashes matching; exit `1` means a listed source file is missing or mismatched; exit `2` means invalid arguments or unsafe/unreadable input. The helper has no `--expect-commit` option; do not invent one or claim that a hash match proves the pinned revision.
