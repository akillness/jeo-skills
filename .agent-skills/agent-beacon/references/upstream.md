## Source-verified scope

- The pinned [README](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/README.md) describes Beacon as an open-source, local-first cross-harness session-history and memory layer. It normalizes sessions, prompts/responses, tool calls, commands, file activity, approvals, MCP activity and token usage into one inspectable event model. The local runtime JSONL is under `~/.beacon/endpoint/logs/runtime.jsonl`; the local dashboard and trace commands read local state.
- The pinned [CLI README](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/cli/beacon/README.md) lists the public command families and states that per-user paths are the default; `--system` is for root-managed deployment. The CLI module source [go.mod](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/cli/beacon/go.mod) declares Go `1.27.0` and toolchain `go1.27.2`; the hook module [go.mod](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/cli/beacon-hooks/go.mod) declares the same. These are source requirements, not a measured build result.
- [Endpoint install](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/docs/cli/endpoint-install.mdx) writes collector/runtime/harness configuration and may start a launchd/systemd/supervised service. It discovers supported runtimes by default; `--harness` can constrain selection, and `--dry-run` prints planned actions without changing endpoint files or services. `--no-start` writes files without starting the service. Backfill reads recent local session stores; `--no-backfill` or `BEACON_BACKFILL=0` disables it. Interactive setup signs in and preselects Beacon Cloud with an explicit Local opt-out; signing in alone forwards nothing. Confirming Managed installs and connects, while `--connect` requests the same post-install attempt.
- [Endpoint connect](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/docs/cli/endpoint-connect.mdx) is the opt-in/revocable Beacon Cloud forwarding path. It can stage a bounded last-30-day session backfill (up to 24 MiB) and writes device-specific credentials/configuration. `--no-backfill` disables the history upload. Privacy mode is chosen by onboarding or `--privacy-mode standard|metadata-only`: `standard` retains the captured content allowed by local redaction/limits; `metadata-only` omits prompt text, responses/reasoning, tool arguments/results, command output, diffs and raw payloads but still retains structured metadata such as command lines, file paths, tool/MCP names, ids, hashes and token usage. `disconnect` stops forwarding and removes local credentials by default; `--keep-credentials` retains them for reuse. Revoking the server-side device is a separate dashboard action.
- [Endpoint status](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/docs/cli/endpoint-status.mdx) is observational: it reports config, runtime log, collector/service state, harnesses, diagnostics and destination status. `--json` is machine-readable; status does not by itself establish runtime readiness, network reachability or healthy service recovery.
- [Endpoint traces](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/docs/cli/endpoint-traces.mdx) `list`, `search` and `show` read local JSONL and optional local SQLite history only; they do not contact the network. `reindex` is a local mutation: it creates or updates `history.db` and may retention-prune, so it requires explicit approval. `history.db` is opt-in and stores redacted retained trace content; `reset` deletes that history. `endpoint uninstall` removes it with runtime logs unless `--keep-logs` is supplied.
- [Memory](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/docs/cli/memory.mdx) is a local review workflow. `beacon memory evaluations run --dry-run` previews selected traces and evaluator calls without a network request; the non-dry-run evaluation path is the only workflow command that can call Jev (or SubQ). Candidate creation, approval, rejection and supersession are explicit review steps. Approved memory is project-scoped in local `memory.db`; `memory skills preview` is non-writing, while `memory skills install` writes `.agents/skills/<slug>/SKILL.md` unless an existing file is protected by the command's overwrite policy.
- [Lenses](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/docs/cli/lenses.mdx) are single-file local HTML views. List/add/remove/show/spec/data/lint/preview do not touch the network; `add` asks for confirmation because a lens sees the full trace content it is shown. The sandbox blocks ordinary network APIs but cannot prevent every browser exfiltration mechanism. `preview` is a running loopback server (default `127.0.0.1:8766`) and ends only when stopped.
- [Share](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/docs/cli/share.mdx) is explicit upload to the configured Beacon API. `--print` or `--dry-run` prints the exact payload and sends nothing; read it before sharing a session that touched secrets. Visibility is `direct` (default for a new link; anyone with the bearer link can view it, though it is not listed), `private` or `public`; public sharing asks for confirmation unless `--yes` is supplied. Credentials are sent only in the request authorization header and are not printed or written into the local share record. Cloud Metadata-only mode constrains share payloads to the same metadata boundary.
- [MCP connect](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/docs/cli/mcp-connect.mdx) edits detected harness configuration to register the remote `beacon-managed` server; `connect` keeps backups and records what it wrote without storing tokens. OAuth is the default; token mode references an environment variable. `--dry-run` plans without writing. `status` is read-only and `--check` performs a URL check. A Cloud OAuth connection with write access can share sessions, publish lenses, submit finding feedback, and create/review memory candidates; personal tokens are read-only, and integration approval does not imply approval for those write actions. This is distinct from local `beacon mcp serve`, which exposes local activity/memory over stdio or loopback HTTP only; never bind it to a non-loopback interface.
- [Endpoint uninstall](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/docs/cli/endpoint-uninstall.mdx) unloads the service and removes managed endpoint files. `--keep-logs` preserves runtime logs/history. `--keep-config` preserves harness telemetry configuration and connected enrollment/device key; on macOS system installs it also retains `/Library/Application Support/Beacon/Forwarders`, which may contain S3/GCS/Falcon forwarder credentials. It does not revoke a server-side device; revoke that separately from the Beacon Endpoints dashboard.
- The hook source [config.go](https://github.com/Asymptote-Labs/agent-beacon/blob/cfbd7b1d721664e3b1b5ca2fca5eac4327532c07/cli/beacon-hooks/internal/config/config.go) defaults state under `~/.beacon`, with per-harness directories such as `claude`, `cursor`, `opencode`, `qwen`, `cline`, and `kimi`; hook logs rotate at 10 MiB with five numbered archives. These are source defaults, not evidence that any host has those files.

## Preflight helper contract

From the `jeo-skills` repository root:

```bash
python3 .agent-skills/agent-beacon/scripts/preflight.py --repo /absolute/path/to/upstream --json
```

From an installed skill root:

```bash
python3 scripts/preflight.py --repo /absolute/path/to/upstream --json
```

`--repo` must be an explicit absolute, non-symlink source directory. With no `--repo`, the helper performs only tool discovery and manifest validation and may exit `0` with `source_checked: false`. With `--repo`, exit `0` means every listed file was inspected and its bytes matched; `1` means a listed file is missing or mismatched; `2` means invalid, unsafe, or unreadable input. It is Python-stdlib-only and reads/hash-checks only the public files listed in [`source.json`](source.json); it uses no network, subprocesses, Beacon execution, secret reads, Git HEAD checks, dependency verification, or runtime tests. The JSON report reports `scope: offline-selected-files`, `whole_revision_verified: false`, and `runtime_verified: false`. There is no `--expect-commit` option; do not invent one or treat selected hashes as whole-revision proof.
